# koishi-plugin-group-assistant

[![npm](https://img.shields.io/npm/v/koishi-plugin-group-assistant?style=flat-square)](https://www.npmjs.com/package/koishi-plugin-group-assistant)

面向 Koishi 的群聊治理插件，提供内容审核、刷屏治理、分级处罚、成员管理和治理记录。

当前版本：**1.1.0**

## 功能亮点

### 内容审核

- 红线词命中后立即处理消息，并按违规次数执行对应处罚。
- 敏感词命中后交由 DeepSeek 结合上下文复核，确认违规后再处理。
- 处罚提醒可以显示违规原因和实际命中的关键词。
- 支持红线词库、敏感词库按群独立维护。

### 刷屏治理

- 识别短时间内连续发送大量消息的刷屏行为。
- 识别持续保持较高发送频率的消息行为。
- 发现刷屏后及时处理消息，并根据用户的累计违规情况执行不同级别的处罚。
- 可以分别开启或关闭两类刷屏检测。

### 分级处罚

管理员可以配置多级处罚策略，每一级都可以设置：

- 需要达到的违规次数。
- 警告、禁言或踢出。
- 禁言时长。
- 群内提醒内容。

默认处罚策略：

| 级别 | 同类违规次数 | 处罚 |
| ---: | ---: | --- |
| 1 | 1 次 | 警告 |
| 2 | 3 次 | 禁言 10 分钟 |
| 3 | 5 次 | 禁言 60 分钟 |

### 词库管理

在 Koishi Console 的“群治理词库”页面可以：

- 添加、编辑、启用、禁用和删除关键词。
- 切换红线词库和敏感词库。
- 搜索关键词。
- 上传 TXT 文件批量导入。
- 选择群聊并分别维护每个群的词库。
- 分页查看大量关键词。

### 成员和入群管理

- 配置入群申请暗号，自动处理包含暗号的申请。
- 黑名单用户的入群申请自动拒绝。
- 新成员入群自动发送欢迎语。
- 成员退群自动发送退群通知。
- 白名单用户跳过自动群治理。
- 群主和群管理员自动跳过自动处罚。

### 审计记录

- 查看命中的消息、违规原因、处理动作、AI 复核结果和累计次数。
- 查看当前仍在累计窗口内的违规用户。
- 清零指定用户的累计违规状态。
- 审计记录和违规用户均支持分页查看。

## 安装与使用

### 安装

在 Koishi 项目中安装：

```bash
npm install koishi-plugin-group-assistant
```

然后在 Koishi 配置中启用 `group-assistant`，并确保数据库服务已经启用。

### 初次使用

1. 打开 Koishi Console，进入“群治理词库”。
2. 在左侧添加并选择需要治理的群聊。
3. 选择红线词库或敏感词库。
4. 添加关键词，或上传 UTF-8 TXT 文件批量导入。
5. 在插件配置中选择治理强度和处罚策略。
6. 需要使用敏感词 AI 复核时，开启 AI 复核并填写 DeepSeek API Key。

建议先使用“均衡”治理强度运行，再根据审计记录调整策略。

## 词库管理

### 红线词库和敏感词库

| 词库 | 适合放入的内容 | 命中后的处理 |
| --- | --- | --- |
| 红线词库 | 无需结合语境即可确定违规的关键词 | 立即处理，并累计内容违规 |
| 敏感词库 | 可能出现在正常讨论、引用或科普中的关键词 | 交由 AI 复核，确认后处理 |

红线词库应保持准确，敏感词库用于覆盖需要结合上下文判断的内容。

### TXT 导入格式

- 一行一个关键词。
- 使用 UTF-8 编码。
- 空行和以 `#` 开头的行会被忽略。
- 单个文件最大 2 MB。
- 最多 100000 行。
- 单个关键词最多 200 个字符。

导入完成后，页面会显示读取、新增、重复和无效数量。

## 配置说明

配置页面按用途分为五组。

### 基础设置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `welcomeMessage` | 内置欢迎语 | 新成员入群时发送的内容，支持 `{username}`、`{botName}` |
| `leaveMessage` | 内置退群语 | 成员退群时发送的内容，支持 `{userId}` |
| `botName` | 空 | 欢迎语中的机器人名称 |
| `signal` | 空 | 入群申请暗号 |
| `adminUserIds` | 空数组 | 补充管理员用户 ID |

### 群治理设置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 群治理总开关 |
| `governancePreset` | `balanced` | 宽松、均衡、严格或自定义 |
| `punishmentLevels` | 3 级 | 累计处罚策略 |
| `offenseWindowHours` | 24 | 自定义模式下的累计违规时间窗口 |
| `auditRetentionDays` | 30 | 审计记录保留天数 |

### 内容检测

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `contentDetectionEnabled` | `true` | 开启红线词和敏感词检测 |

### 行为检测

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `behaviorDetectionEnabled` | `true` | 开启行为检测 |
| `burstDetectionEnabled` | `true` | 开启短时间刷屏检测 |
| `sustainedRateDetectionEnabled` | `true` | 开启持续高频检测 |

### AI 复核

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `aiReviewEnabled` | `false` | 开启敏感词 AI 复核 |
| `apiKey` | 空 | DeepSeek API Key |
| `model` | `deepseek-v4-flash` | `deepseek-v4-flash` 或 `deepseek-v4-pro` |

AI 复核只用于敏感词。红线词和刷屏行为由本地治理策略直接处理。

## 治理强度

| 预设 | 短时间刷屏 | 持续高频 | 适合场景 |
| --- | --- | --- | --- |
| 宽松 | 15 秒内 10 条 | 较高发送速率 | 活跃群、通知较多的群 |
| 均衡 | 10 秒内 6 条 | 中等发送速率 | 大多数普通群，推荐起点 |
| 严格 | 8 秒内 4 条 | 较低发送速率 | 消息刷屏较多、需要强治理的群 |
| 自定义 | 自行设置 | 自行设置 | 需要精细调整的群 |

选择“自定义”后，可以调整以下行为参数：

| 参数 | 默认值 | 作用 |
| --- | ---: | --- |
| `burstWindowSeconds` | 10 | 短时间刷屏的统计时间范围 |
| `burstMessageCount` | 6 | 统计范围内的触发消息数 |
| `burstCooldownSeconds` | 60 | 同一轮刷屏再次累计处罚的间隔 |
| `burstRecoverySeconds` | 15 | 刷屏状态恢复所需的平静时间 |
| `sustainedBucketCapacity` | 30 | 持续高频检测允许的短时消息额度 |
| `sustainedRefillPerMinute` | 18 | 持续高频检测每分钟允许的消息额度 |
| `sustainedConfirmSeconds` | 20 | 持续超出速率后确认违规所需的时间 |

## 处罚模板

每一级处罚的 `messageTemplate` 留空时，不发送群内提醒，只执行处罚。

支持的变量：

| 变量 | 含义 |
| --- | --- |
| `{at}` | 被处罚用户的 @ |
| `{reason}` | 处罚原因；内容违规会附带命中的关键词，行为违规会显示行为原因 |
| `{action}` | 当前处罚动作 |
| `{muteMinutes}` | 禁言时长 |
| `{offenseCount}` | 当前同类违规次数 |
| `{level}` | 当前处罚级别 |

示例：

```text
{at} 因【{reason}】已被禁言 {muteMinutes} 分钟，当前同类违规 {offenseCount} 次。
```

## 管理员指令

以下指令需要群主、群管理员或 `adminUserIds` 中的管理员执行。

### 审计和违规状态

```text
违规记录
违规记录 -n 20

违规用户
违规用户 -n 20

违规清零 <userId>
```

- `违规记录`：查看最近的治理记录，最多 30 条。
- `违规用户`：查看当前累计窗口内的违规用户。
- `违规清零 <userId>`：清除指定用户的累计违规状态，不删除历史审计。

### 白名单和黑名单

```text
白名单.添加 <userId> [原因]
白名单.删除 <userId>
白名单.列表

黑名单.添加 <userId> [原因]
黑名单.删除 <userId>
黑名单.列表
```

白名单用户跳过自动群治理。黑名单用户的消息会被撤回，入群申请会被拒绝，并参与违规累计。

### 手动处置

```text
警告 <userId> [原因]
处罚 <userId> [原因] -a warn
处罚 <userId> [原因] -a delete
处罚 <userId> [原因] -a mute
处罚 <userId> [原因] -a kick
```

手动处置会写入审计并参与累计处罚。

## 权限和注意事项

- 群主和群管理员会自动跳过自动处罚。
- 如果适配器无法识别管理员身份，将管理员 ID 填入 `adminUserIds`。
- 自动撤回、禁言和踢出需要机器人具备对应群权限。
- 词库、审计记录和违规状态依赖 Koishi 数据库。
- 建议先使用均衡预设，再根据实际审计记录调整。

## 原理与调参建议

### 消息处理流程

```text
收到群消息
  -> 管理员、白名单检查
  -> 内容检测和行为检测
  -> 选择处理方式
  -> 撤回消息或提交 AI 复核
  -> 累计违规
  -> 执行处罚
  -> 保存治理记录
```

管理员和白名单用户直接放行。红线词、黑名单和刷屏可以立即处理；敏感词先经过 AI 判断，确认违规后进入处罚流程。

### 内容检测

内容检测会将消息与当前群的红线词库、敏感词库进行匹配，并对消息和关键词做一致的文本处理，以识别常见的大小写、全半角、空白、标点和简单混淆变化。

调参建议：

- 确定违规、无需语境判断的词放入红线词库。
- 可能出现在正常对话中的词放入敏感词库。
- 红线词库优先保证准确，避免加入含义过于宽泛的词。
- 发现误判时，优先调整词库分类，而不是直接关闭整个内容检测。

### 刷屏检测

刷屏治理分为两类：

- **短时间刷屏**：观察一个较短的时间范围内发送了多少条消息，适合处理连续发送。
- **持续高频**：观察一段时间内的整体发送速度，适合处理持续发送的高频消息。

两类检测可以同时开启。短时间检测更关注突然爆发，持续高频检测更关注长期保持高发送速度。

调参建议：

- 普通群使用均衡预设。
- 正常消息很多时，增大 `burstMessageCount` 或使用宽松预设。
- 高频刷屏明显时，缩短 `burstWindowSeconds` 或使用严格预设。
- 细水长流的高频消息较多时，降低持续高频的允许速率。
- 误伤正常通知时，可以提高触发门槛，并将固定通知账号加入白名单。

### 冷却、恢复和累计次数

- **冷却时间**控制同一轮刷屏中再次累计处罚的间隔，避免同一轮行为反复增加违规次数。
- **恢复时间**表示用户平静一段时间后，当前刷屏状态结束。
- **累计违规窗口**决定过去的违规次数保留多久。

恢复刷屏状态不会清除累计违规次数。累计窗口结束后，历史次数自然失效；管理员也可以使用 `违规清零` 立即清除指定用户的累计状态。

### 处罚策略

处罚级别按照同类违规次数生效：

- 第一次违规可以警告。
- 多次违规可以禁言。
- 持续违规可以进一步延长禁言或踢出。
- 将提醒模板留空，可以只执行处罚而不发送群内通知。

建议先观察审计记录中的实际命中情况，再调整处罚次数和动作。
