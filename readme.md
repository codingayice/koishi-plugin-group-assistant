# koishi-plugin-group-assistant

[![npm](https://img.shields.io/npm/v/koishi-plugin-group-assistant?style=flat-square)](https://www.npmjs.com/package/koishi-plugin-group-assistant)

面向 Koishi 的群聊治理插件。插件使用“确定性规则同步处置 + 敏感内容异步 AI 复核”的治理模型，提供入群审核、双词库、反刷屏、黑白名单、处罚升级和审计能力。

## 核心能力

- 双词库：红线规则命中后立即处置，敏感规则只进入 DeepSeek 异步复核。
- 风险信号：内容、行为和名单检测分别产出信号，再按动作优先级统一裁决。
- 大词库匹配：关键词使用 Aho-Corasick 自动机，单次扫描可匹配多条规则。
- 反绕过归一化：处理全半角、大小写、零宽字符、空白、标点、重复字符和部分常见混淆写法。
- 行为治理：支持可调的瞬时刷屏，以及 Bigram Dice 优先、编辑距离兜底的长窗口相似复读检测。
- 异步 AI 队列：有界并发、超时、重试和消息级幂等，不阻塞消息主链路。
- 多级处罚：可自由配置处罚级数、触发次数、警告/禁言/踢出动作、禁言时长和逐级提醒模板。
- 群级隔离：规则、黑白名单、行为状态和违规状态均按群隔离。
- 审计记录：保存风险信号、证据、处置动作、AI 状态和同类违规次数。
- 入群管理：支持入群暗号、黑名单拒绝、欢迎语和退群通知。

群主、群管理员和 `adminUserIds` 中的补充管理员不会受到自动处罚。群管理员由适配器提供的成员角色自动识别，通常不需要手动配置。

## 治理流程

```text
群消息
  -> 权限与白名单检查
  -> 提取纯文本并生成关键词与相似度视图
  -> 名单、内容和行为检测器产出风险信号
  -> 本地策略选择优先级最高的确定性动作并累计同类违规
  -> 根据当前违规次数匹配处罚阶梯
  -> 红线与行为风险同步处置
  -> 敏感规则进入异步 DeepSeek 复核
  -> AI 确认后由本地策略决定撤回或禁言
  -> 写入审计与当前累计窗口内的同类违规状态
```

动作优先级固定为：

```text
kick > mute > delete > warn > silent
```

插件不使用内容分、行为分或风险等级。红线命中不会被正常行为抵消，刷屏也不依赖内容评分。

用户提醒与管理员审计相互隔离。群内提醒只显示“消息内容违反群规”“发送频率异常”等公开原因，不显示具体关键词、规则 ID、检测窗口、消息数量或相似度阈值；完整的 `pattern` 和 `evidence` 只保存在管理员审计中。撤回属于对当前违规消息的即时处理，处罚阶梯中的警告、禁言和踢出属于对用户的累计处罚，两者可以同时执行。

## 配置

### 基础设置

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `welcomeMessage` | 内置欢迎语 | 入群欢迎信息，支持 `{username}` 和 `{botName}` |
| `leaveMessage` | 内置退群语 | 退群通知，支持 `{userId}` |
| `botName` | 空 | 欢迎语中的机器人名称 |
| `signal` | 空 | 入群申请需要包含的同意暗号；为空时不自动处理普通申请 |
| `adminUserIds` | `[]` | 适配器无法识别管理员时的补充管理员用户 ID |

### 群治理设置

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 启用群治理 |
| `governancePreset` | `balanced` | 治理强度：`relaxed`、`balanced`、`strict`、`custom` |
| `punishmentLevels` | 3 级 | 多级累计处罚配置，最多 10 级；留空可关闭累计处罚 |
| `burstDetectionEnabled` | `true` | 启用瞬时刷屏检测 |
| `similarDetectionEnabled` | `true` | 启用相似复读检测 |
| `auditRetentionDays` | `30` | 审计记录保留天数 |

治理预设：

| 模式 | 瞬时刷屏 | 相似复读 |
| --- | --- | --- |
| `relaxed` | 15 秒 10 条 | 5 条，Dice 0.82 / 编辑距离 0.90 |
| `balanced` | 10 秒 6 条 | 3 条，Dice 0.75 / 编辑距离 0.86 |
| `strict` | 8 秒 4 条 | 3 条，Dice 0.70 / 编辑距离 0.82 |
| `custom` | 读取自定义参数 | 读取自定义参数 |

处罚阶梯独立于治理预设，在所有模式下都使用 `punishmentLevels`。默认配置为：

| 级别 | 同类违规次数 | 动作 | 禁言时长 |
| ---: | ---: | --- | ---: |
| 1 | 1 | 警告 | - |
| 2 | 3 | 禁言 | 10 分钟 |
| 3 | 5 | 禁言 | 60 分钟 |

每个处罚级别支持以下字段：

| 字段 | 范围 | 含义 |
| --- | --- | --- |
| `offenseCount` | 1～100 | 达到该同类违规次数后启用本级处罚 |
| `action` | `warn` / `mute` / `kick` | 警告、禁言或踢出 |
| `muteDurationMinutes` | 1～10080 | 禁言时长，仅 `mute` 生效 |
| `messageTemplate` | 空 | 本级群内提醒模板；留空时静默执行处罚 |

模板支持 `{at}`、`{reason}`、`{action}`、`{muteMinutes}`、`{offenseCount}` 和 `{level}`。模板有内容时发送群内处罚通知，留空时直接执行处罚而不通知。级别会按 `offenseCount` 从小到大整理；违规次数增长后，插件从所有已达到的级别中选择最强处罚，同为禁言时选择时长更长的一项，防止错误配置导致处罚降级。配置为空数组时只保留规则自身的撤回等即时处理，不再执行累计警告、禁言或踢出。

以下高级参数只在 `governancePreset` 为 `custom` 时生效：

| 配置项 | 默认值 | 范围 | 含义 |
| --- | ---: | ---: | --- |
| `burstWindowSeconds` | 10 | 5～60 | 瞬时刷屏统计窗口 |
| `burstMessageCount` | 6 | 3～20 | 窗口内触发刷屏的消息数 |
| `similarWindowMinutes` | 60 | 10～1440 | 相似消息统计窗口 |
| `similarMessageCount` | 3 | 2～10 | 触发相似复读的消息数 |
| `similarityThreshold` | 0.86 | 0.75～0.95 | 编辑距离相似度阈值 |
| `diceSimilarityThreshold` | 0.75 | 0.60～0.95 | 字符 Bigram Dice 相似度阈值 |
| `similarMinLength` | 10 | 4～50 | 参与相似检测的最短文本长度 |
| `offenseWindowHours` | 24 | 1～168 | 同类违规累计窗口 |

`burstDetectionEnabled` 和 `similarDetectionEnabled` 可以分别关闭两种行为检测，在所有预设下都有效。

### AI 复核设置

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `aiReviewEnabled` | `false` | 启用敏感规则异步复核 |
| `apiKey` | 空 | DeepSeek API Key |
| `model` | `deepseek-v4-flash` | `deepseek-v4-flash` 或 `deepseek-v4-pro` |

AI 只复核敏感关键词。红线、黑名单、短时刷屏和相似复读均由本地确定性策略处理。AI 未启用、队列已满、超时或返回格式错误时，敏感消息默认不处罚并保留审计状态。

## 内置工程参数

| 参数 | 内置值 |

## 词库与规则管理

规则管理统一在 Koishi Console 的“群治理词库”页面完成。进入页面后填写目标群号，可以上传 UTF-8 TXT 词库，也可以直接新增单条关键词；规则列表支持按分类筛选、编辑关键词、修改红线/敏感分类、启用/停用和删除。

词库导入默认追加，不覆盖已有规则。导入过程中会忽略空行和 `#` 开头的注释，使用与消息匹配相同的归一化逻辑进行去重，并返回读取、新增、重复和无效数量。单次导入上限为 2 MB、100000 行，单个关键词最多 200 个 Unicode 字符。
Console 页面会在上传后显示解析和批量写入进度，服务端会校验 UTF-8 编码、文件大小、行数和关键词长度。

词库导入入口只有 Koishi Console 的“群治理词库”页面：打开控制台侧边栏，填写目标群号，选择红线或敏感分类后上传 UTF-8 TXT 文件。该页面要求当前 Console 账号具备管理员权限，服务端会复用相同的解析、去重和批量写入流程；上传内容只通过 WebSocket 传输，不会在插件中额外保存文件，也不会新增数据库表。

红线词应只存放无需语境也能确定违规的内容。存在引用、讨论、科普等正常语境的词应放入敏感词库。

## 审计与违规状态

```text
违规记录
违规记录 -n 20
违规用户
违规用户 -n 20
违规清零 123456
```

- `违规记录`：查看最近 10 条审计，`-n` 最大为 30。
- `违规用户`：查看当前累计窗口内仍有效的同类违规状态。
- `违规清零 <userId>`：清除该用户在当前群的累计状态，不删除历史审计。

AI 审计状态包括：

| 状态 | 含义 |
| --- | --- |
| `pending` | 已进入 AI 队列 |
| `confirmed` | 本地规则或 AI 已确认违规 |
| `dismissed` | AI 判定不违规 |
| `skipped` | AI 未启用或缺少 API Key |
| `failed` | 队列已满、超时或复核失败 |
| `duplicate` | 同一消息已经提交过复核 |

## 黑白名单

```text
白名单 添加 123456 助教账号
白名单 删除 123456
白名单 列表

黑名单 添加 123456 广告账号
黑名单 删除 123456
黑名单 列表
```

白名单用户跳过自动治理。黑名单用户的入群申请会被拒绝，已在群内的黑名单用户发言会被撤回，并参与同类违规累计。

## 手动处置

```text
警告 123456 刷屏提醒
处罚 123456 广告引流 -a warn
处罚 123456 广告引流 -a mute
处罚 123456 恶意行为 -a kick
```

- `警告 <userId> [reason]`：发送警告并记录一次手动处置。
- `处罚 <userId> [reason] -a <action>`：支持 `warn`、`delete`、`mute`、`kick`。

手动 `delete` 没有目标消息 ID，因此只记录审计。自动撤回、禁言和踢出依赖适配器提供相应 API；平台不支持或机器人权限不足时会保留审计并写入日志。

## 匹配与安全设计

- 关键词规则和规则内容使用相同的归一化流程，然后进入 Aho-Corasick 索引。
- 相似检测先计算字符 Bigram 多重集合 Dice，命中后直接返回；Dice 未命中时再使用编辑距离兜底。
- 编辑距离使用阈值带宽和行级提前终止，长度差超过上限时无需构建完整矩阵。
- 行为状态按“群 ID + 用户 ID”存储，包含空闲清理和 10000 用户容量保护。
- AI 输出经过固定 JSON 结构校验，模型不能直接指定撤回、禁言或踢出动作。

当前 AI 队列保存在进程内，适合单实例机器人。多实例部署或要求重启后继续消费时，应将任务队列和行为窗口迁移到 Redis 等共享存储。

## 日志排查

插件日志使用 `group-assistant`、`content-moderation` 和 `event-handlers` 三个 logger 分类，开发环境可直接查看终端输出。日志不会输出 API Key，消息治理日志也只记录群、用户、消息、规则 ID、信号和处理状态等诊断信息。

词库导入可按以下顺序排查：

- `收到 Console 词库导入`：服务端已收到控制台上传请求。
- `Console 词库文件解码失败`：文件不是合法的 UTF-8，或超过文件大小限制。
- `词库解析失败`：文件大小、行数或关键词格式不符合导入限制。
- `词库导入完成`：数据库写入流程已结束，可结合新增、重复、无效和失败数量定位问题。

群治理可按以下关键词排查：

- `重建群治理规则缓存`：数据库规则已重新加载并编译为 Aho-Corasick 索引。
- `关键词匹配成功`：消息命中了红线或敏感规则。
- `触发刷屏检测`、`触发相似复读检测`：行为引擎产生了治理信号。
- `提交 AI 复核任务`、`开始 AI 复核`：敏感词消息进入异步复核。
- `AI 复核请求失败`、`AI 复核队列已满`：需要检查 API 配置、网络、额度或队列压力。
- `消息撤回成功`、`禁言成功`、`踢出成功`：适配器动作已执行；对应的失败日志通常表示机器人权限或适配器能力不足。

```bash
npm install
npm run typecheck
npm test
npm run build
```
